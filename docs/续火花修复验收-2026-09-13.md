| 范围 | 修复后的行为 |
| --- | --- |
| 好友匹配 | 从原始目标定位不冲突的身份，阻止同名昵称、备注链将一个人的目标扩展到另一个人的 ID；当前聊天仅通过标题区域的精确匹配确认。 |

| 提交与续传 | 发送前持久化 `pending`；页面核验通过后记录 `submitted`。结果不明确时保留 `pending`，不计为完成，不自动再次提交；最终写盘失败只重试写盘。 |
| 收件人状态 | 已确认的稳定身份使用独立记录键，并保存 `recipient_identity` 与原始 `target`。同一人的 ID、昵称和备注共享状态，`pending` 优先；兼容旧原文键及 `sent_at` 记录。 |
| 代理错误 | 上游请求超时或响应回填失败后终止浏览器请求，避免再次通过浏览器重放可能已受理的发送请求。 |
| 线上超时补修 | 隐藏会话跳过，点击等待不超过 5 秒，同一失败候选不在列表中反复点击；输入事务保留同一个编辑器节点，避免占位属性消失后换行/回车定位失效。 |
| 资料加载 | 发送前遍历并复位好友列表，先收集昵称及 API 身份再读取当日提交状态；此补修的实际匹配效果尚未通过线上续传验证。 |
| 登录就绪 | 登录提示消失后才使用聊天界面；短暂显示登录提示时继续等待，在原定期限后仍显示登录页才报告登录未完成，不再立即断言 Cookie 失效。 |
| 完成统计 | 所有未完成目标都进入失败汇总，包括始终没有被选中的好友；同一人使用多个已确认别名时，按已有提交记录完成统计，不重复发送。 |
| 工作流 | 两个实际执行 `dev` 代码的工作流统一状态缓存前缀，真实发送仅从默认分支触发；取消后仍尝试保存状态并上传备份。触发脚本先解析和校验默认分支。 |
