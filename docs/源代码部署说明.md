# 源代码部署说明

> 前提：确保您已获取到所有配置，详见：[【DouYinSparkFlow 配置生成器】使用说明](配置生成器使用.md)

源码部署方式较为灵活，可部署在本地设备、云服务器，或青龙/白虎等任务面板环境中。需要注意的是，本项目通过无头浏览器模拟人工操作，运行时会对设备性能和浏览器运行环境有一定要求，具体表现请以实际测试结果为准。

本项目基于 Python 开发。选择源码部署方式，默认您已具备基础的 Python 项目运行与环境配置能力。

## 1. 克隆项目

首先拉取当前仓库到对应设备`https://github.com/2061360308/DouYinSparkFlow.git`

## 2. 安装项目依赖

安装依赖`pip install -r requirements.txt`

## 3. 填写环境变量

首先在项目根目录下创建`.env`文件

之后打开已经填写好的配置生成器页面，点击配置生成器左侧最下方` 复制 .env 配置文件 `按钮，得到内容粘贴到`.env`文件中。

## 4. 运行

项目根目录下执行`python main.py`即可。

## 5. Linux 生产服务器（推荐使用 systemd timer）

不要再依赖临时 crontab 或手动执行。仓库内的 `deploy/huohua-production.service`
和 `deploy/huohua-production.timer` 会在每天北京时间 09:00 自动运行，并在服务器
重启或错过执行时间后补跑。

先准备专用用户、虚拟环境和两个配置文件：

```bash
sudo useradd --system --home /opt/huohua --shell /usr/sbin/nologin huohua || true
```

- `/etc/huohua-tasks.json`：任务数组；每项至少包含 `unique_id`、`targets`
- `/etc/huohua-cookies.json`：单账号可直接放 cookie 数组；多账号使用
  `{ "unique_id": [ ...cookies ] }` 映射

配置文件需要允许 `huohua` 用户读取（Cookie 文件建议权限设为 `0640`）：

```bash
sudo chown huohua:huohua /etc/huohua-tasks.json /etc/huohua-cookies.json
sudo chmod 0640 /etc/huohua-tasks.json /etc/huohua-cookies.json
```

然后把仓库部署到 `/opt/huohua/fire`，安装依赖和浏览器，并执行：

```bash
sudo install -d -o huohua -g huohua /etc/huohua /var/lib/huohua /var/log/huohua
sudo chown -R huohua:huohua /opt/huohua/fire
sudo install -m 0644 deploy/huohua-production.service /etc/systemd/system/
sudo install -m 0644 deploy/huohua-production.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now huohua-production.timer
```

检查调度器和最近一次运行：

```bash
systemctl list-timers huohua-production.timer
systemctl status huohua-production.timer
cat /var/lib/huohua/last-run.status
journalctl -u huohua-production.service -n 100 --no-pager
```

只有全部目标都完成页面提交核验时，服务才会返回成功。这里的核验是输入框清空、
当前聊天出现本次消息且未出现新的发送失败提示，不等同于服务端送达回执或火花已续成。
状态保存在 `/var/lib/huohua/delivery-state.json`；普通本地运行默认使用
`logs/delivery-state.json`，也可通过 `DELIVERY_STATE_FILE` 指定位置。

程序在按发送键前记录 `pending`，页面核验通过后改为 `submitted`。重启只会自动处理
尚未尝试提交的目标；`pending` 会保留并使任务报告未完成，防止网络超时或写盘失败后
重复发送。遇到 `pending`，先核对对应账号和好友的聊天记录：确认已发送后可将该条
状态改为 `submitted`；确认未发送后才删除该目标的当天记录以允许重试。不要清空整个
状态文件。已确认身份的记录使用 `@recipient:<字段>:<ID>` 作为键，并保存原始 `target`
和 `recipient_identity`；核对时根据这些字段定位记录。ID、昵称和备注只有经当前映射
确认为同一人时才共享状态，同名的不同好友不会合并。`message_hash` 用于核对本次
内容，不保存消息明文。旧版带有 `sent_at` 的记录继续作为当日已提交记录使用。

如果生产环境通过 GitHub Actions 运行而不是本机浏览器运行，请把
`deploy/trigger_huohua.sh` 安装为 cron 调用脚本。它默认触发正式
`schedule.yml`（`main` 分支），由该工作流检出当前的 `dev` 修复版本，并校验
GitHub 返回码、等待运行完成及记录失败原因。`schedule_dev.yml` 仅用于手动调试。
